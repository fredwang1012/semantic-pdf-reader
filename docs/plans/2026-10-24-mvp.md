# Semantic PDF reader: MVP through library mode, plus the eval harness

Spec: the Notion page "Semantic PDF search reader" (summarised in Goal below). Scope: Tiers 1 to 3, and the
text-side harness for Tier 4. ColQwen visual retrieval is out of scope (it needs a GPU); the harness is built so a
third retriever can be added later.

## Goal

A PDF reader where you type a question and it jumps to the right page and highlights the passage that answers it.
The original PDF page is shown in a PDF.js viewer (not reflowed text), with hybrid BM25 + dense search, a persistent
multi-PDF library, search across the whole library with results grouped by document, and a recall@k / MRR eval
comparing BM25-only against hybrid.

Tier "done when" checks from the spec:
- Tier 1: a natural-language question lands on the right page of a paper.
- Tier 2: exact-term queries (e.g. an acronym) and fuzzy queries both work; the matching passage is highlighted.
- Tier 3: multi-PDF persistent index, re-adding a file is incremental, results grouped by document.
- Tier 4 (harness only): recall@k and MRR, plus latency and index size, for each retriever on a question set.

## What already exists (commit 0f9c507, branch `main`)

`backend/` is a uv project (Python 3.12) ported from github.com/fredwang1012/talkback's retrieval:

- `app/pdftext.py`: `extract(bytes|path) -> (list[Block], list[PageSize])`. Block = lines with `page` (1-based) and
  `bbox` (x0, y0, x1, y1 in PDF points, top-left origin). Drops page-number-only blocks. `join_lines` re-joins words
  hyphenated across lines. `title_of(source, fallback)`.
- `app/chunks.py`: `Chunk(id, page, text, rects)` with `rects = [[page, x0, y0, x1, y1], ...]` one per line.
  `make_chunks(blocks)`: target 600 / min 250 / max 1000 chars, breaks at block boundaries, splits over-long blocks
  between lines, may span pages.
- `app/retrieval.py`: `Index(chunks, embeddings, embedder)`, `.mode` ("hybrid" | "bm25"), `.search(q, k) -> list[Hit]`
  (Hit = chunk + score, best first). Score = 0.6 cosine + 0.4 min-max BM25. BM25-only search drops zero-score hits.
- `app/embedder.py`: multilingual-e5-small via the optional `embed` extra; `get_embedder()` returns None when
  `settings.embed == "off"` or sentence-transformers is missing.
- `app/library.py`: `Library(root, embedder)` storing `data/docs/<16-hex sha256 prefix>/{doc.pdf, meta.json,
  chunks.json, embeddings.npy}`. `add` (dedupes by hash, raises `NoTextLayer` for scans), `list`, `get`, `pdf_path`,
  `delete`, `index` (cached). `DocMeta(id, title, filename, pages, chunks, page_sizes, embedded, added)`.
- `app/main.py`: FastAPI. `GET /api/health`, `GET /api/docs`, `POST /api/docs` (multipart `file`; 400 not a PDF,
  413 too large, 422 no text layer), `GET /api/docs/{id}`, `GET /api/docs/{id}/pdf`, `DELETE /api/docs/{id}` (204),
  `GET /api/docs/{id}/search?q=&k=` -> `{mode, results: [{id, page, text, rects, score}]}`. Serves
  `frontend/dist` at `/` when built.

None of it has tests yet, and it has never been run.

        "Momentum smooths noisy updates by adding a fraction of the previous update to the current one.",

def make_pdf(pages: list[list[str]] = PAGE_TEXTS, title: str = "") -> bytes:
    doc = pymupdf.open()
    for n, paras in enumerate(pages, start=1):
        page = doc.new_page(width=612, height=792)
        y = 72
        for para in paras:
            box = pymupdf.Rect(72, y, 540, y + 120)
            page.insert_textbox(box, para, fontsize=11)
            y += 140
        page.insert_text((300, 760), str(n), fontsize=9)  # a page number footer, which extraction drops
    if title:
        doc.set_metadata({"title": title})
    data = doc.tobytes()
    doc.close()
    return data


@pytest.fixture
def sample_pdf() -> bytes:
    return make_pdf()


class FakeEmbedder:
    """Concept vectors: words map to shared dimensions, so "plants making food" lands near photosynthesis without
    sharing a single word with it (what BM25 alone would miss)."""
    CONCEPTS = [
        {"photosynthesis", "plants", "plant", "chlorophyll", "light", "glucose", "food", "leaves", "sugar"},
        {"gradient", "descent", "optimizer", "optimiser", "learning", "rate", "adam", "training", "step"},
    ]

    def _vec(self, text: str) -> np.ndarray:
        words = set(text.lower().replace(".", " ").replace(",", " ").split())
        v = np.array([len(words & c) for c in self.CONCEPTS], dtype=np.float32) + 1e-3
        return v / np.linalg.norm(v)

    def embed_query(self, text: str) -> np.ndarray:
        return self._vec(text)

    def embed_passages(self, texts: list[str]) -> np.ndarray:
        return np.stack([self._vec(t) for t in texts])

    monkeypatch.setattr(settings, "embed", "off")

### Task 4: PDF viewer with passage highlights

Files: create `frontend/src/viewer/geometry.ts`, `frontend/src/viewer/PdfViewer.tsx`, `frontend/test/geometry.test.ts`.

1. `geometry.ts` (pure, no DOM):
   - `highlightBoxes(rects: Rect[], page: number, scale: number): Box[]` where
     `Box = {left, top, width, height}` in CSS pixels: only rects on `page`, scaled, padded by 2px on every side
     (clamped at 0 for left/top), and boxes on the same text line (vertical overlap >= 50% of the smaller height)
     whose horizontal gap is <= 6px after scaling merged into one.
   - `firstRect(rects)`: the rect with the lowest page, then lowest y0 (where to scroll).
   - `fitScale(pageWidthPt, containerWidthPx, max = 2)`: scale so the page fits the container width minus 32px of
     padding, never above `max` and never below 0.25.
2. `PdfViewer.tsx`: props `{ url: string; pageSizes: [number, number][]; target: { rects: Rect[]; key: number } |
   null }`.
   - Loads the document with `pdfjs-dist` (`getDocument(url)`), worker set up the Vite way:
     `import workerUrl from "pdfjs-dist/build/pdf.worker.min.mjs?url"; GlobalWorkerOptions.workerSrc = workerUrl;`
   - Lays out every page up front as a placeholder of the right size (from `pageSizes` and the fit scale, recomputed
     on container resize), so scrolling to page N works before it is rendered.
   - Renders a page's canvas only when it is near the viewport (IntersectionObserver, rootMargin ~ one screen);
     renders at `devicePixelRatio` for sharpness; cancels a pending render task when a page is torn down or the scale
     changes; destroys the document on unmount or URL change.
   - When `target` changes (new `key`), scrolls so the first highlighted rect sits about a third of the way down the
     viewport (smooth scroll), and draws the `highlightBoxes` for every page the rects touch as absolutely
     positioned divs over the canvas, using the highlight colour token, with a short fade-in.
   - Shows a page number label under each page and a loading / error state.
3. `geometry.test.ts`: filtering by page, scaling, padding and clamping, merging two adjacent same-line rects,
   not merging rects on different lines, `firstRect` across pages, `fitScale` bounds.
4. Frontend tests, typecheck and build pass. Commit: "PDF viewer with passage highlights".

### Task 6: Retrieval eval harness

Files: create `backend/app/evaluate.py`, `backend/eval/README.md`, `backend/eval/questions.example.jsonl`,
`backend/tests/test_evaluate.py`.

1. Question file format (JSONL), one per line: `{"question": str, "file": str, "pages": [int, ...]}` where `file` is
   the PDF's file name in the eval folder and `pages` are the 1-based pages that answer it (any one counts).
2. `evaluate.py`, runnable as `py -3.12 -m uv run python -m app.evaluate <pdf folder> <questions.jsonl> [--k 1 3 5
   10] [--retrievers bm25 hybrid]`:
   - Builds an index per PDF with the same `extract` + `make_chunks` path as the library (in memory, no writes to
     `data/`), once per retriever ("bm25": no embedder; "hybrid": `get_embedder()`, skipped with a clear message
     when it is None).
   - A question's rank is the position of the first hit whose page (any page in its rects) is in `pages`,
     searching only that question's PDF.
   - Reports per retriever: recall@k for each k, MRR (reciprocal rank, 0 when not found in the top max(k)),
     median and p95 query latency in ms, index build time, and index size (chunk count, embedding bytes). Prints a
     Markdown table and, with `--json out.json`, writes the raw numbers and per-question ranks.
   - Pure functions (`recall_at_k(ranks, k)`, `mrr(ranks)`, `rank_of(hits, pages)`) are separate from the CLI so
     they can be tested; `None` means not found.
   - A retriever is a small callable registry keyed by name, so a visual retriever (ColQwen) can be added later
     without touching the metric code.
3. `eval/README.md`: how to build the ~30-question set over the CSC2626 Week 5 papers (NPI, NTP, TACO, GTI, Motion
   Grammar, Baker et al.): put the PDFs in `backend/eval/` (gitignored), write `questions.jsonl` with the page
   numbers checked by hand, mix of exact-term questions (acronyms, equation names) and paraphrased ones, then run
   the command. `questions.example.jsonl` holds 3 illustrative lines.
4. Tests: metric functions on hand-made rank lists (including all-missing and empty), `rank_of` with multi-page
   rects, and an end-to-end run of the CLI's main function on a temp folder with a `make_pdf` PDF and 2 questions,
   checking BM25 recall@1 is 1.0 and the Markdown table has the expected columns.
5. Backend suite passes. Commit: "Retrieval eval harness: recall@k, MRR, latency, index size".
